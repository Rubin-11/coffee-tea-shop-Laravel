# 📋 Планы (docs/plans/)

> Планы — полноценные артефакты репозитория (по принципам harness engineering).
> Сложная работа фиксируется в плане с журналом прогресса и решений, чтобы агенты
> могли работать без внешнего контекста (чаты, заметки, головы людей).

## Структура плана

Каждый план — один файл `docs/plans/YYYY-MM-<короткое-название>.md`:

```markdown
# План: <название>

- **Статус:** активный | завершён | отменён
- **Создан:** YYYY-MM-DD
- **Цель:** <что делаем и зачем, критерий готовности>

## Шаги
1. [ ] Шаг 1 — что делаем, где
2. [ ] Шаг 2 — ...

## Журнал
- YYYY-MM-DD: начали; сделано X; решили Y (почему)
```

## Правила

1. План создаётся ДО начала сложной работы (несколько файлов/дней/риск).
   Для мелких правок достаточно короткого описания в задаче.
2. Статус плана обновляется в журнале: что сделано, что решено и **почему**.
3. Завершённый план не удаляется — остаётся как история решений.
4. Известные технические недоработки фиксируются в `docs/TECH-DEBT.md`.
5. Ссылку на активный план добавляют в AGENTS.md (карта проекта).
