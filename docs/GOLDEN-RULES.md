# 🥇 Золотые принципы проекта

> Механические правила с чёткой позицией. Это не пожелания, а **обязательные инварианты**: нарушение = отказ от принятия работы.
> Основано на принципах harness engineering (OpenAI) и адаптировано под Coffee-Tea Shop.

## 1. Человек управляет, агент выполняет

- Код пишется только по явной задаче. Без задачи — ничего не менять.
- Агент предлагает план → ждёт согласования → выполняет → отчитывается.
- При неопределённости — **спросить**, а не гадать.

## 2. Тесты — арбитр истины

- Перед коммитом — `make test`: все тесты должны проходить (сейчас 286).
- Новая логика → новые тесты. Меняешь поведение → обнови тесты.
- «У меня локально работает» — не аргумент; CI — единственный судья.

## 3. Архитектура: логика в сервисах, контроллеры тонкие

- `app/Services/` — бизнес-логика; контроллеры только связывают HTTP и сервисы.
- Слои соблюдаются механически (PHPStan + структурные тесты), а не «по договорённости».
- Не дублировать логику: общее — в сервисы, повторяющееся — в компоненты.

## 4. Изменения БД — только миграциями

- Схема меняется через `make migrate`. Руками таблицы не редактировать.
- Сиды/фабрики — единый источник тестовых данных.

## 5. Валидация на границе

- Входные данные проверяются в Form Requests (или на границе сервиса), не «где-то по ходу».
- Никаких необработанных пользовательских данных в запросах к БД.

## 6. Коммиты — Conventional Commits, на русском

- `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:` — по одному типу на коммит.
- Один коммит = одна логическая единица работы.

## 7. Документация живёт вместе с кодом

- Изменил код → обнови соответствующий файл в `docs/`.
- Документация — система записи; AGENTS.md — карта-оглавление, не энциклопедия.
- Планы сложной работы — в `docs/plans/` (см. README там).

## 8. Не ломать существующее

- Рефакторинг и фичи не должны ломать текущие тесты и поведение.
- Если что-то сломалось — почини до сдачи, а не «оставь как есть».

## 9. Стиль и качество — автоматически

- Pint — формат кода обязателен (CI проверяет).
- PHPStan level 5 — статический анализ обязателен (CI проверяет).
- Стиль «под человеческий вкус» не гоняем; важны корректность и читаемость для будущих агентов.

## 10. Чистота репозитория

- Не коммитить: `vendor/`, сгенерированные файлы, секреты, локальные конфиги (`.env`).
- Медиа товаров — часть проекта (хранятся в git), но лишний мусор не заносить.
